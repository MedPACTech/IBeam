# IBeam.Tests.Management.Diagnostics

Run `dotnet test IBeam.Tests.Management.Diagnostics -c Release`. Unit tests require no external resources. Set IBEAM_MANAGEMENT_TEST_STORAGE to a private Azurite Table connection to enable the seven StorageIntegration cases; without it they are inconclusive. Never use production storage. Fixtures explicitly create and remove only random tables.

Tests cover 24-hour defaults, UTC/offset date boundaries, fixed-query pagination, empty/filtered continuations, row/request/time budgets, missing records, live authorization before each provider read, tag isolation and strict configuration. Token tests cover tampering, purpose/type/source/app/environment/query/key replay boundaries, expiry and nonrenewing lifetime. Real-provider tests inspect exact partition/date filters and column selection, preserve row ETags, verify no reader writes/schema creation, and exercise table-scoped read-only SAS.

Run IBeam.Tests.Management.Credentials and IBeam.Tests.Management for shared service/repository and API boundary regressions. Base/reader-only registration keeps error routes absent; explicit error API registration installs the safe routes and capability.

HTTP coverage (IBM-0084) uses the real named machine scheme, live credential guard, internal reader, safe public projection, MVC model binding and detailed host middleware. Tests prove opt-in route discovery in either registration order; safe paging/detail envelopes; anonymous/customer/human/legacy/revoked/expired/other-deployment denial; independent error/log grants; safe invalid-input and missing/foreign ID responses; source/trace suppression; sanitized provider failures in responses/audit/service logs; timeouts/cancellation; missing-repository startup rejection; and absence of write routes. An additional real-provider case serves both routes using a table-scoped read-only SAS and verifies unchanged ETag/content. Four StorageIntegration cases now require the private Azurite variable.

Log coverage (IBM-0085/IBM-0086) mirrors the error suite: default window, frozen filters on continuation, reader-side filter recheck, filter validation before storage, shared-source suppression, scan budgets, live Logs.Read before each read, tamper/expiry/foreign-source/cross-type token rejection, fixed projection and strict options. HTTP tests cover opt-in routes, filter round trips without echo/audit, capability composition with errors, independent grants, denial modes, safe 400/404/503/504 envelopes and no write routes. Three StorageIntegration cases seed canaries in every excluded SystemLogs column plus EntityChange, SelectRollup, tenant-partition and malformed rows, and assert only operational System rows are returned, excluded columns are never selected, filters are pushed down and escaped, rows are unchanged, and a read-only SAS serves the routes without canary leakage into responses, audit or service logs.
