# IBeam.Tests.Management.Identity

Tests the optional support Identity adapter and selected HTTP endpoints with the real IBeam Azure Table, password, MFA, token and session services. HTTP fixtures use temporary signing/OTP secrets and a capturing email sender; no external email is sent or production credentials required.

Run `dotnet test IBeam.Tests.Management.Identity -c Release`. Set IBEAM_MANAGEMENT_TEST_STORAGE to an isolated Azurite table connection for the StorageIntegration cases, including the HTTP authentication fixtures. Set IBEAM_MANAGEMENT_TEST_SEPARATE_STORAGE to a second isolated endpoint for the Separate storage-isolation case. Shared mode uses the first endpoint with distinct prefixes. Without the fixture variables, the dependent integration cases are inconclusive; configuration/unit tests still run. Never use production storage. Each integration case creates random table prefixes and cleans only those fixture tables.

Coverage includes shared/separate identity isolation, explicit idempotent bootstrap, MFA-only token issuance, named bearer trust boundaries, live role/membership/session revocation, refresh rotation/replay, disabled support memberships/organizations, forbidden enrollment/recovery routes, administrator-only support disable and runtime configuration validation. Also run IBeam.Tests.Identity.Services after changes to the shared password/MFA implementation, and IBeam.Tests.Management to retain bring-your-own-auth coverage.
