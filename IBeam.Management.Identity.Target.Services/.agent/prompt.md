# IBeam.Management.Identity.Target.Services

Read the repository .agent/implementation-guide.md before changes. This optional module runs inside the customer application's target host, not the support Identity host. Preserve API -> Services -> Repository, explicit named machine authentication, live credential checks and app/environment/Identity realm binding. No automatic customer membership for support staff, no customer principal impersonation, no direct portal DB access. Custom operations use IServiceOperationExecutor and metadata-only Management audit. Advertise only installed operations with usable adapters. Do not log keys, actor assertions, Identity profiles, tokens, OTPs or raw provider errors. IBM-0098 installs discovery only; tenant/user operations and delegated actors are later cards.

IBM-0105 tenant administration uses existing Identity lifecycle services, stable operation IDs and separate source/reference/phase metadata. Recovery resumes owned pending lifecycle work without another customer row or destructive rollback. Missing provenance is unknown. Consumer hooks must deduplicate by operation ID; customer AuthUserId stays null.

IBM-0106 lookup derives an existing receipt ID from the same canonical scoped idempotency identity as Execute, without needing or persisting the customer payload. Never invoke mutation handlers or change receipts during lookup. Keep app/org/realm/current authority and expiry checks; 404 is not proof that an in-flight write failed.

IBM-0107 enterprise onboarding uses host-allowlisted policy keys and stable tenant/invite intent IDs. Separate encrypted private recovery input from metadata-only receipts/audit; retain the operation-derived recovery key across instances and retention. SMTP claims use journal ETags; unknown delivery never auto-resends. Processing success is not customer acceptance: business completion requires verified recipient, redeemed invite and active approved membership. No customer inviter/support impersonation. See docs/management/enterprise-onboarding.md.

IBM-0108 operation query projections may enrich onboarding receipts from authoritative state but never resume workflows/send email. Retry can read the original onboarding create receipt only under the complete retry matrix, then executes the existing intent. Completed customer acceptance is read-only. Preserve whole-call deadlines and safe metadata audit.

IBM-0109 provisioning is invitation-only, with host policy/target-local approved roles. Never use eager membership bootstrap or modify a global user before verified acceptance. roles.read is independent of roles.assign. Scope idempotency to the fixed tenant route; never derive request identity from a mutable recipient/body. Recipient/policy journal deduplication reuses one native invite across keys; unknown delivery never auto-resends. See docs/management/customer-provisioning.md.

IBM-0110: invitation transitions require exact ETags, stable operation IDs and native verified acceptance claims before membership. No claim stealing or automatic resend after SMTP uncertainty. Keep private ciphertext separate from safe receipts/audit and enforce target-owned roles/rate/redirect policy. See docs/management/customer-invitation-lifecycle.md.
